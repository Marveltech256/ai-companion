# Implementation extension: Phases 6–10

The user authorized continuation through Phase 10 on 2 November 2026, then clarified on 3 November that Figma is the visual inspiration for an interactive application. The subsequent companion-direction correction is documented in the [audit and acceptance evidence](companion-direction-audit.md). The shipped interface uses native Flutter widgets in `lib/application/`; the exported frames remain an archived reference. The Flutter/Firebase/Supabase/OpenAI services remain in place. Cloud activation awaits target-project inspection and server configuration.

Work in order: (6) explicit preferences and consented interaction personalization; (7) opt-in proactive scheduling with timezone/frequency/quiet hours and private push payloads; (8) bounded microphone turns, backend transcription, the existing text/memory engine, and generated speech in the supplied voice screen; (9) supportive conversation guidance and voluntary reflections/activity/goal discussions; (10) exact-project identity policies, consent, scoped export, erasure, revocation checks, and storage denial.

The interactive interface now includes a timezone/day/time/quiet-hour editor, learning and memory consent, privacy/account-erasure controls, individual memory editing/expiry, and account dialogs. Missing cloud configuration produces an unavailable state. The separately labelled device workspace persists a real personal journal and manual memories without producing an assistant reply. See [interactive application notes](interactive-application.md).

All migrations are local candidates until the existing Supabase schema can be inspected. Live providers, real push delivery, APNs, Android/iOS hardware audio, browser Firebase configuration, and destructive cloud flows require separate verification. No paid provider calls or actual notifications are part of local tests.

## Implemented behavior

**Personalization:** `learning_enabled` defaults to false, independently of memory. Opted-in completed turns update counts and average user-message length once per idempotent request. Disabling learning deletes these observations. Explicit communication style, response length, interests, and user-approved memory take precedence; no psychological, diagnostic, demographic, or inactivity-based profile is inferred. The learning switch is available in **Our rhythm**. Device journals do not infer interaction patterns.

**Proactivity:** notification preferences require an IANA timezone, chosen days/times, and quiet hours before enabling. Users choose up to three daily slots and a cap from one to three; the default cap remains one. Local-date/slot deduplication covers repeated daylight-saving hours. Saved work/sleep windows and overnight/date exceptions apply. Existing dialogs now confirm local date/time reminders, reject ambiguous/nonexistent DST times, and expose cancellation/history. The model cannot create a reminder by saying it has done so. Device registrations use Firebase's FID registration API and remain server-only. Registration is off by default. The worker persists personalized content to an owned conversation; FCM carries generic copy and opaque routing IDs, without private names, memories or transcript excerpts.

Delivery uses leases, per-device preference/routine/quiet-hour rechecks, source/version and consent fences, collapse identifiers, and a short expiry capped at quiet/routine/day boundaries. An uncertain result is `unknown` and is not automatically resent. History distinguishes provider acceptance from received/opened app acknowledgements. Acceptance is not proof of display; already accepted work cannot be recalled. Real delivery still needs testing. Changing reminder permission alone does not create an event. The client resolves the destination through its verified owner-scoped API, rather than trusting a payload conversation ID.

**Voice:** the existing Figma voice screen now supports explicit microphone turns. Capture is PCM16, mono, 16 kHz, at most 60 seconds/1.92 MB. The verified backend transcribes the WAV, the existing conversation service persists the transcript and reply, and speech synthesis reads only the user's completed saved assistant message. Long replies are split into bounded speech segments. Captions, interruption, end/return, microphone-denial errors, account-change cancellation, and background stopping use existing controls/text regions.

Recorded input is held in memory and is not uploaded to Firebase Storage or retained as an audio file by Morrow. Text transcripts are saved as conversation messages under the conversation retention setting; structured memory remains separately controlled. Generated speech may use private temporary playback files on native platforms; these are cleaned after playback and at the next launch. Stopping or changing identity prevents late responses from being applied, but a provider request already accepted may still finish. No provider-retention guarantee is implied. The privacy note identifies OpenAI and AI speech. Voice selection currently uses the server-configured built-in voice; no voice-picker layout was invented.

**Companionship:** the home invitation uses an explicitly selected interest, with optional wording. Conversation instructions support listening, user-invited reflections, music/activity ideas, and manageable user-chosen goal steps. They prohibit diagnosis, medical outcome promises, exclusivity, emotional obligation, invented memories, and claims of unavailable tools. Local tests verify instruction and context contracts; live model-quality and safety evaluation remain required.

**Privacy:** data-bearing user endpoints verify the Firebase signature/project and current account status. Ordinary requests cache the revocation/disabled lookup for at most 15 seconds; sensitive export/new-erasure operations force a fresh lookup. Erasure-status polling requires a valid signed token and can continue after identity removal until that token expires. The SQL identity configuration requires the exact Firebase issuer, with scoped RLS and service-only write functions. Direct client database/Realtime access is not used; review revocation requirements before enabling it.

Exports use owner-scoped pages rather than an unbounded database response. **Our rhythm → Export your story** downloads JSON in a browser, capped at 25 MB in the client, and discards an export if the account changes. It omits push identifiers, server credentials, and internal leases. On native platforms an explicit dialog copies the export as JSON for the user to save; it does not send that data to another application automatically.

Account erasure requires exact confirmation and a recent authenticated session. Anonymous accounts use a freshly issued token because they have no reusable sign-in credential. Linked accounts use the new recent-authentication dialog. A durable erasure record blocks access and profile recreation, disables notifications, deletes device registrations, cascades application data, and then removes the Firebase user. Failures remain pending/failed and can resume; completion is recorded only after both stores succeed. A minimal UID/status tombstone remains to block stale-token resurrection and support retries. Backup/provider retention and the tombstone retention policy require release review. No real cloud account has been erased by this work. Device-workspace removal deletes only that workspace's local storage key.

Conversation and memory retention are separate. Conversation deletion removes transcript/history and extraction jobs; a saved memory can retain its source quote with its source-message link cleared. Forgetting structured memories does not erase transcripts or independently created reminders. The privacy cleanup worker removes expired records, one-day voice-usage metadata, 90-day device registrations, 30-day check-in records, and one-year consent audit records. Deploy and monitor the cleanup schedule; it is not active yet. Storage rules default to denying file access because no persistent file-upload feature is approved.

## Activation and verification

Use [backend setup](backend-setup.md) for the six functions, environment variables, and migration inventory. After target-project inspection, schedule `checkin-dispatch` every minute and `privacy-maintenance` at an appropriate bounded interval (for example every five minutes), using `POST` and a server/Vault-held `SCHEDULER_SECRET`. Never put that secret in a client or plaintext checked-in schedule. No schedule has been created.

For Apple delivery, configure the APNs key in Firebase and the Apple Push Notifications capability/provisioning. The project includes APNs entitlements with development for Debug and production for Profile/Release, plus the Firebase Messaging delegate setup. These have not been compiled on a Mac. Browser push is deliberately unavailable until its Web Firebase/VAPID/service-worker configuration is provided and tested.

Before production, test real microphones, Bluetooth/audio interruptions, mobile background transitions, generated speech playback, notifications with two accounts/devices, timezone changes, daylight-saving boundaries, provider failures, erasure retries, storage rules, and cloud RLS. Verify newly designed consent/privacy flows against Figma and run live supportive-conversation evaluations. Local compilation and provider doubles cannot establish these outcomes.
